fix(deploy): say which D1 database is reused, repair old schemas

Reusing an existing database by name is correct (redeploys must not create
duplicates), but it happened silently, so binding an account's pre-existing
`outlook-email-db` looked arbitrary.

- cf-deploy.mjs logs the reuse explicitly with name + uuid, and points at
  D1_DB_NAME for databases that were created under another name
- the reuse path also re-syncs database_name when it differs from the binding
- migrate.ts probes sqlite_master for *every* table the schema declares instead
  of only `settings`, so an older database missing push_state / tags /
  account_tags gets those tables added on the next request (existing rows are
  untouched) rather than failing at query time
- tests: partial-schema repair, failed attempts are not memoised
- README / GUIDE note the reuse behaviour and that a stored
  settings.login_password_hash takes precedence over ADMIN_PASSWORD
